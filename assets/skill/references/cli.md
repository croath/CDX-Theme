# CLI (`/path/to/cdxthemex`)

Thin CLI over shared library **`cdx-theme-core`**. Invoke as **`/path/to/cdxthemex`**; saved probes as **`/path/to/run.sh <name>`**. Resolve placeholders in repo `AGENTS.md`.

Pack, unpack, apply, restore, adjust appearance, and **verify** multi-app portable theme packages (`.cdxtheme`) over CDP.

| Format | `format` field | Extension |
|--------|----------------|-----------|
| **CDXTheme** | `cdxtheme` | `.cdxtheme` |

Legacy single-file formats (`.codex-theme` with top-level `manifest` + `css`) are **not** supported.

Upstream CLI docs: monorepo `cdx-theme-app-open` → `cli/README.md` (binary name there may be `cdxtheme`; this skill uses **`/path/to/cdxthemex`** as resolved by host `AGENTS.md`).

## Command overview

```text
/path/to/cdxthemex theme pack <SOURCE> [OPTIONS]
/path/to/cdxthemex theme unpack <INPUT> <OUTPUT>
/path/to/cdxthemex theme merge-css <SOURCE> [-t codex|workbuddy]
/path/to/cdxthemex apply --app codex|workbuddy --theme <PACKAGE> [OPTIONS]
/path/to/cdxthemex restore [--app codex|workbuddy] [OPTIONS]
/path/to/cdxthemex detect [--json]
/path/to/cdxthemex appearance <dark|light|system> [OPTIONS]
/path/to/cdxthemex verify inject [-t PACKAGE]
/path/to/cdxthemex verify layout [--contexts chat,work]
/path/to/cdxthemex probe [--tab chat|work] [--expr JS]
/path/to/cdxthemex screenshot -o OUT.jpg [--tab chat|work]
```

### Hosts & CDP ports

| Host | Default CDP | Targets | Notes |
|------|-------------|---------|--------|
| `codex` | **9335** | `app://` | ChatGPT / Codex desktop |
| `workbuddy` | **9336** | `file://` (asar renderer) | WorkBuddy AI Electron app |

`apply` / `restore` select the host with **`--app`** (default `codex`). Port defaults follow the host; override with `--port`.

`detect` reports install path, process state, and default-port CDP reachability for each host.

`verify` / `probe` / `screenshot` are **Codex-oriented** (default port **9335**). For WorkBuddy inject checks, pass `--port 9336` where the subcommand accepts it (e.g. `verify inject --port 9336`). Layout probes and screenshots target Codex Chat/Work UI.

### `theme pack`

**`theme-dir`** is a skill variable: the directory of one theme (`theme.json` + partials + assets). Resolve it from host **`AGENTS.md`** (single-theme: often `.`; multi-theme monorepo: often `src/<theme-id>`). Packages go under **`output/`** (or host-defined pack output):

```bash
# from repo root
/path/to/cdxthemex theme pack theme-dir -o output/theme.cdxtheme --force

/path/to/cdxthemex theme pack theme-dir/theme.json -o output/example-theme.cdxtheme
/path/to/cdxthemex theme pack theme-dir --pretty --force
/path/to/cdxthemex theme pack theme-dir --no-merge-css   # skip partial merge
```

| Flag | Description |
|------|-------------|
| `-o`, `--output` | Output path (default `{id}-{version}.cdxtheme`) |
| `--pretty` | Pretty-print JSON |
| `--force` | Overwrite existing file |
| `--no-merge-css` | Skip in-memory partial merge into the package |

**Source layout**

When packing a directory, the CLI looks for source JSON in this order:

1. `theme.json`
2. `manifest.json` (if `theme.json` is missing)

```text
theme-dir/
  theme.json
  codex/                 # partials (source of truth; edit these)
    00-palette.css       # primary --theme-* (light + dark) when present
    00-tokens.css
    01-shell.css
    …
  workbuddy/
    00-palette.css
    00-tokens.css
    …
  codex.css              # generated by merge-css (optional on disk)
  workbuddy.css
  assets/hero.jpg
```

```json
{
  "schemaVersion": 1,
  "id": "example-theme",
  "displayName": "Example",
  "version": 1,
  "copy": { "brandTitle": "…" },
  "targets": {
    "codex": {
      "css": "codex.css",
      "options": {
        "rendererProfile": "codex-theme-v1",
        "baseTheme": { "mode": "dark", "accent": "#DC0000" }
      }
    },
    "workbuddy": { "css": "workbuddy.css" }
  },
  "images": { "hero": "assets/hero.jpg" }
}
```

`version` in theme source is an **integer** (skill convention). The package embeds that version.

### `theme merge-css`

Concatenate split CSS partials into the root files declared in `theme.json` → `targets.*.css`.

```bash
/path/to/cdxthemex theme merge-css theme-dir
/path/to/cdxthemex theme merge-css theme-dir -t codex
/path/to/cdxthemex theme merge-css theme-dir --target workbuddy
```

| Input | Output |
| --- | --- |
| `codex/*.css` (alphabetical) | `codex.css` |
| `workbuddy/*.css` | `workbuddy.css` |

- Numeric prefixes (`00-palette.css`, `00-tokens.css`, `01-shell.css`, …) control order.
- Generated files start with a “do not edit by hand” banner.
- **`theme pack` merges partials in memory** into the `.cdxtheme` (does **not** write root `codex.css` / `workbuddy.css`). Skip with `--no-merge-css`. Use `theme merge-css` to materialize root CSS files.
- Prefer editing partials only — see skill **CSS partials** map for which file to open.

### `apply`

Inject a theme package into a live host app over CDP.

1. Probe CDP on the remote-debugging port
2. If not connected, launch (or restart) the host with `--remote-debugging-port`
3. Inject the package CSS/skin into live page targets

The package must declare the matching `targets.codex` / `targets.workbuddy` CSS.

```bash
# Codex (default --app codex, port 9335)
/path/to/cdxthemex apply --app codex --theme output/example-theme.cdxtheme
/path/to/cdxthemex apply -t ./output/mercedes-f1.cdxtheme --port 9335

# WorkBuddy (port 9336 by default)
/path/to/cdxthemex apply --app workbuddy -t ./output/example-theme.cdxtheme
/path/to/cdxthemex apply --app workbuddy -t ./output/example-theme.cdxtheme --port 9336
```

| Flag | Description |
|------|-------------|
| `--app` | Host app id: `codex` (default) or `workbuddy` |
| `-t`, `--theme` | Path to `.cdxtheme` |
| `--port` | CDP port (default `9335` codex / `9336` workbuddy) |
| `--timeout-ms` | Wait / inject timeout (default `120000`) |

### `restore`

Remove the injected CSS/skin from live renderer targets (inverse of `apply` inject).

1. Probe CDP on the remote-debugging port
2. If not connected, launch (or restart) the host with remote debugging
3. Strip injected theme DOM / early scripts from matching page targets

Does **not** rewrite `~/.codex/config.toml` appearance keys (use `appearance` for mode).

```bash
/path/to/cdxthemex restore
/path/to/cdxthemex restore --port 9335 --timeout-ms 120000
/path/to/cdxthemex restore --app workbuddy
/path/to/cdxthemex restore --app workbuddy --port 9336
```

| Flag | Description |
|------|-------------|
| `--app` | Host app id: `codex` (default) or `workbuddy` |
| `--port` | CDP port (default `9335` codex / `9336` workbuddy) |
| `--timeout-ms` | Wait / restore timeout (default `120000`) |

### `appearance`

Set ChatGPT / Codex host appearance mode by writing `[desktop].appearanceTheme` in `~/.codex/config.toml`.

Supported modes: **`dark`**, **`light`**, **`system`**.

When the value changes, Codex is restarted with remote debugging so the mode takes effect (unless `--no-restart`).

```bash
/path/to/cdxthemex appearance dark
/path/to/cdxthemex appearance light
/path/to/cdxthemex appearance system
/path/to/cdxthemex appearance dark --no-restart
/path/to/cdxthemex appearance light --config /path/to/config.toml
```

| Flag / arg | Description |
|------------|-------------|
| `MODE` | `dark`, `light`, or `system` |
| `--config` | Config path (default `~/.codex/config.toml`) |
| `--port` | CDP port used when restarting Codex (default `9335`) |
| `--no-restart` | Only write config; skip Codex restart |

WorkBuddy appearance is not controlled by this command (Codex/`~/.codex/config.toml` only).

### `verify`

Check live host over CDP. Default port **9335** (Codex). Pass `--port 9336` for WorkBuddy inject checks.

```bash
# Inject state: host classes, style tag, theme id/version, image vars
/path/to/cdxthemex verify inject
/path/to/cdxthemex verify inject -t output/<theme-id>.cdxtheme
/path/to/cdxthemex verify inject -t output/<theme-id>.cdxtheme --port 9336

# Layout contracts (Codex): Chat fixed composer, Work util+composer stack, ribbon, hero
/path/to/cdxthemex verify layout
/path/to/cdxthemex verify layout --contexts chat,work --json-out /tmp/layout.json
```

| Subcommand | Exit 0 | Exit 1 |
| --- | --- | --- |
| `inject` | all targets `pass: true` | any fail |
| `layout` | no layout issues | one or more issues |

### `probe`

Quick DOM snapshot or custom JS (Codex CDP, default **9335**):

/path/to/cdxthemex probe

### `screenshot`

Capture a JPEG of live **Codex** via CDP (default port **9335**):

```bash
/path/to/cdxthemex screenshot -o /tmp/chat.jpg --tab chat
/path/to/cdxthemex screenshot -o /tmp/work.jpg --tab work --quality 80
```

| Flag | Description |
|------|-------------|
| `-o`, `--output` | Output JPEG path |
| `--port` | CDP port (default `9335`) |
| `--tab` | `chat` or `work` before capture |
| `--wait-ms` | Wait after tab switch (default `900`) |
| `--quality` | JPEG quality 1–100 (default `70`) |

### Iteration loop (theme authoring)

After editing theme CSS partials under `theme-dir/codex/` or `workbuddy/`:

```bash
/path/to/cdxthemex theme merge-css theme-dir   # optional; pack auto-merges
/path/to/cdxthemex theme pack theme-dir -o output/<theme-id>.cdxtheme --force

# Codex
/path/to/cdxthemex apply -t ./output/<theme-id>.cdxtheme
/path/to/cdxthemex verify layout
/path/to/cdxthemex verify inject -t output/<theme-id>.cdxtheme
/path/to/cdxthemex probe --tab work
/path/to/cdxthemex screenshot -o /tmp/work.jpg --tab work

# WorkBuddy
/path/to/cdxthemex apply --app workbuddy -t ./output/<theme-id>.cdxtheme
/path/to/cdxthemex restore --app workbuddy   # clear inject when needed
/path/to/cdxthemex verify inject -t output/<theme-id>.cdxtheme --port 9336

# Saved layout probes (Codex hero / util stack / ::before) — see scripts/probe/README.md
/path/to/run.sh go-work-home
/path/to/run.sh work-layout
/path/to/run.sh set-mode chat
/path/to/run.sh chat-layout
```

When changing the Codex composer, re-check **Chat home**, **Work home**, and **conversation detail** (detail needs relative layout; see [codex.md](codex.md)).

When changing WorkBuddy CSS, re-check **home** (header / tabs / composer) and **conversation** (detail composer); see [workbuddy.md](workbuddy.md).

## Package JSON

```json
{
  "format": "cdxtheme",
  "schemaVersion": 1,
  "exportedAt": "…",
  "theme": { "id": "…", "displayName": "…", "version": 1, "copy": { } },
  "targets": {
    "codex": {
      "css": "/* inlined */",
      "options": { "rendererProfile": "codex-theme-v1", "baseTheme": { } }
    },
    "workbuddy": {
      "css": "/* inlined */"
    }
  },
  "assets": {
    "images": {
      "hero": { "filename": "art.png", "mimeType": "image/png", "base64": "…" }
    }
  }
}
```

Max size **30 MB**. Max images **32**. No remote CSS `@import` / `url(http…)`.
